SunPower Code Map

A solar company's CRM: an enquiry becomes a qualified lead, gets a site survey with photos, an admin approves it, and staff send a quote built from a ready-made package with every part listed automatically. This page shows how the code is split between Person A (backend + database) and Person B (frontend), what each file does, and which logic carries the system.

Enquiry→Qualify→Survey + photos→Admin approval→Quote from package→PDF→Won

Person A Backend + database

  • Node 22+ / Express 5: async errors reach the error handler automatically
  • PostgreSQL 17 via pg (node-postgres), plain SQL, no ORM
  • embedded-postgres: a private database server run from node_modules, on port 5433, with no system install
  • bcryptjs, jsonwebtoken (JWT auth), Multer (photo upload), PDFKit (quote PDF)

Person B Frontend

  • React 18 + Vite 5, React Router 6, Tailwind CSS 3
  • Axios client with the token attached to every request
  • Mock/Live switch: a full in-browser mock of the API, so the UI could be built before the backend existed
  • lucide-react icons, canvas-confetti for celebration moments

The core logic

Atomic status moves A

utils/leadStatus.js · config/db.js

transitionLead(client, id, to, actor, note) locks the lead row with SELECT … FOR UPDATE, checks the TRANSITIONS map, updates the status and writes the timeline entry, all on one connection inside BEGIN … COMMIT. Two people clicking at once can't both move the same lead.

Ownership A

utils/access.js

assertLeadAccess() runs on every lead, survey-assignment and quote action. For staff, a lead that isn't theirs returns 404, not 403, so its existence isn't revealed. The inbox filter is forced on the server, and duplicate-phone warnings hide the other lead's details.

Fair auto-assign A

services/leads.service.js

A website enquiry goes to the active staff member with the fewest open leads. pg_advisory_xact_lock handles enquiries one at a time, so two arriving together can't both choose the same "least busy" person.

Packages → parts list A

db/03_packages.sql

One rules table: which package kinds get a part, its section, and a quantity rule. Panels = ceil(kW × 1000 / 540), connector pairs = panels + 2, DC cable = 10 + 10 × kW m, AC cable = 15 + 5 × kW m, stands = kW, batteries = 2 (≤ 2 kW) or 4. The inverter and charge controller are picked by size.

Quote maths A

services/quotes.service.js

calculateTotals(): subtotal = Σ qty × rate; the discount applies to every line before GST; GST is charged per line at the part's rate (5% panels and electronics, 18% others) on the discounted value; everything is rounded to paise. The quote builder uses the same formula, so preview = saved quote.

Price snapshot A

services/quotes.service.js

All quote lines are inserted in one statement with INSERT … SELECT FROM unnest(arrays), copying name, rate, GST and section. Later price changes never alter a quote already issued.

Safe SQL and errors A

all services · middleware/error.js

Every query uses $1, $2 parameters, and LIKE wildcards are escaped in search. Database error codes become clear 400/409 replies in one {success:false, error:{code,message}} format.

Photo uploads A

middleware/upload.js · surveys.controller.js

Multer saves files under random names (the client's file name is never trusted), checks type and size, and the database stores /uploads/surveys/… paths. If the database step fails, the uploaded files are deleted so none are left orphaned.

Mock-first UI B

api/client.js · api/mockData.js

The apiClient sends each call either to an in-browser mock database (saved to localStorage) or to the real server. That let B build and demo every screen before the backend existed, and it's still an offline fallback.

Live adapter A+B

api/liveAdapter.js

Bridges the two halves without rewriting B's pages:

  • snake_case ↔ camelCase
  • renames, e.g. template_id → templateId, total → total_amount
  • review reshaped: {status:'APPROVED'} → {decision:'APPROVE'}
  • datetime-local → ISO time
  • base64 photos → multipart Files

Role-based screens B

App.jsx · LeadDetail.jsx

ProtectedRoute sends each role to its own area. The lead page shows only the action that is valid for the current status (Qualify → Schedule → Review → Create quote), matching the backend's state machine.

Suggested size A

utils/sizing.js

units = bill ÷ ₹8; kW = units ÷ 120 (about 4 units per kW per day), capped by roof area ÷ 100 sq ft and by sanctioned load, then rounded and kept within the 1–5 kW packages. The survey's recommended kW replaces it on approval.

One request end to end: "Create Formal Quote"

  1. QuoteBuilder.jsx (B) sends {template_id, include_installation, discount_percentage, notes} through apiClient.post('/api/leads/5/quotes').
  2. client.js strips /api; liveAdapter.js turns it into {templateId, includeInstallation, discountPct, notes}; axios attaches the JWT.
  3. leads.routes.js → authenticate → authorize(ADMIN, STAFF) → quotes.controller.js validates the IDs, caps the discount at 30% and defaults installation to on.
  4. quotes.service.js opens a transaction:
    • assertLeadAccess locks the lead (404 if it isn't yours), and the status must be SURVEY_APPROVED or QUOTED
    • finds the approved survey, then loads the package and the Installation package of the same size
    • reads the parts list, calculates totals, inserts the quote and all lines in one statement
    • transitionLead → QUOTED, then COMMIT
  5. response.js wraps the reply as {success, data} in camelCase; the adapter maps it back to the page's names, and the page opens QuoteView.jsx. "Download PDF" streams pdf.service.js output.

Tooling and how we work

Running it

  • npm run db:start: bundled Postgres on port 5433
  • npm run dev (backend, port 5000) and npm run dev (frontend, Vite on port 5173)
  • npm run db:migrate -- migrations/001_packages.sql: upgrade, keeping data
  • npm run db:reset: wipe and reload demo data (only before a demo)

Checking it

  • npm run test:smoke: 64 checks covering the whole flow, 409 gates, 403/404 rules, packages, PDF and reassign
  • A separate sunpower_test database plus API_URL keeps tests away from real data
  • Postman/Thunder collection with token-saving login requests

Team workflow

  • The SQL in db/ is the source of truth; schema changes ship as migrations
  • An agreed endpoint contract let A and B build in parallel (B against the mock)
  • Small commits on main; no READMEs or .env files on GitHub
